=== MindIE|MindIE-Motor#137
分类: 配置/参数错误
简述: 构建配置的 v0.30.0 分支在仓库中不存在，切分支失败
错误: error: pathspec 'v0.30.0' did not match any file(s) known to git
根因: 失败发生在被测仓代码拉取后的切分支环节：x86 与 arm 两个构建子任务都在 git checkout 指定版本这一步被 git 拒绝，提示该 ref 在仓库中不存在，脚本随即非零退出，构建在真正编译之前就中止了。原因是流水线为 MindIE-Motor 配置的构建分支/标签（v0.30.0）与仓库实际存在的 ref 不一致——该 tag 尚未创建或已改名，而本次构建使用的版本号为 3.3.0，与 v0.30.0 并非同一套命名，问题出在 CI 构建配置侧，而不是被测代码。

建议: 核对 MindIE-Motor 仓库实际存在的分支与标签，把构建配置里写死的分支/版本参数改成真实存在的 ref（例如与构建版本 3.3.0 对应、确实存在的分支或标签），确认后在同一节点手工执行一次 clone 与 checkout 验证能切到该 ref。

验证方式：重跑该流水线，要求两个架构子任务都能成功 checkout 指定 ref、进入编译阶段并构建成功、整体运行结果为 SUCCESS。

=== MindIE|MindIE-SD#116
分类: 代码编译错误
简述: 插件源码编译报 aclOpExecutor 类型未声明，构建中止
错误: error: ‘aclOpExecutor’ was not declared in this scope
根因: 失败在插件编译环节：x86 与 arm 两个构建子任务都在编译插件源码时，所依赖的 torch_npu 头文件里对销毁算子执行器的函数声明报「类型未声明」，gmake 随即以 Error 1/2 退出，插件构建脚本非零返回，wheel 构建失败。该类型由 CANN 的 ACL 接口提供，报错说明当前 torch_npu 与 CANN/ACL 头文件的版本组合不匹配（或头文件包含顺序影响），属于构建环境依赖不一致导致的问题，不是 MindIE-SD 插件源码本身的语法缺陷。

建议: 对齐构建环境的 torch_npu 与 CANN 版本：确认 torch_npu 头文件所依赖的 ACL 接口（算子执行器类型）在所用 CANN 版本中可见，必要时升级或回退 torch_npu 与 CANN 到相互兼容的版本；若仍不可见，则在插件源码中显式包含 ACL 算子编译相关头文件以消除可见性差异，改好后在构建镜像内手工跑一次插件构建脚本复现。

验证方式：重跑该流水线，要求两个架构子任务的插件编译均通过（不再出现该类型未声明的编译错误）、整体运行结果为 SUCCESS。
